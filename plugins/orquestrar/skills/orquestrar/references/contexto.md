# Contexto

Contexto é o que cada parte do trabalho precisa saber. Pouco contexto gera trabalho genérico; contexto demais gera confusão e custo.

## Inventário rápido

1. **O que já temos:** o pedido, arquivos, conversas anteriores, memória do ambiente, dados nos conectores.
2. **O que falta:** fatos, números, documentos, decisões da pessoa.
3. **Onde buscar:** a própria pessoa, a web (fontes primárias primeiro), os dados dela, código para calcular.
4. **O que é sensível:** dados pessoais, de clientes ou de saúde. Use só o necessário e não espalhe para partes que não precisam.

## Quem precisa saber o quê

Cada parte recebe só o que usa. O revisor recebe os critérios e o artefato, não o raciocínio de quem produziu (senão ele só concorda). Um pesquisador de uma frente recebe a pergunta dele, não as outras.

## Artefatos viajam inteiros

Passe arquivos, links e documentos, não resumos de resumos. Cada resumo perde informação, e a perda é silenciosa.

## Estado do projeto (trabalho longo)

Se o trabalho vai durar mais de uma sessão, crie no início um arquivo de estado e mantenha-o atualizado:

```markdown
# <nome do projeto>

## Objetivo
<resultado e critério de qualidade, em 2 linhas>

## Restrições
- …

## Decisões
- <data> <decisão> (por quê)

## Feito
- …

## Próximo passo
<uma ação concreta>

## Em aberto
- <pergunta para a pessoa>
```

Na sessão seguinte, comece lendo esse arquivo. A pessoa não deveria ter que repetir nada.
